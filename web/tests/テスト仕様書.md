# 深海ダンジョン / StillDepths.jsx テスト仕様書

対象: `deep-sea-dungeon/web/src/StillDepths.jsx`
実行基盤: `web/tests/`(vitest 4 + happy-dom で**本番の JSX そのまま**をレンダリングし、実物のボタンをクリックする)
姉妹作 `rogue-like-dungeon` の `テスト仕様書.md`(Babel+jsdom 独自ハーネス)と同じ考え方・同じカテゴリ命名(SAVE/ITEM/BTL/PROG/AD/UI)を踏襲しているが、実行基盤・ディレクトリは別物。

```bash
cd web
npm run test    # vitest run --config vitest.config.js
```

## 1. この仕様書の使い方

- **IDの付け方**: 領域略号 + 連番(`SAVE-01`, `ITEM-03`…)。実装ファイルは概ね `test*.test.jsx` に1〜3ケースずつ対応。
- **優先度**: `P0` = 資産消失・進行不能・クラッシュにつながる、リリース前に必ず潰す。`P1` = 仕様乖離・バランス破壊。`P2` = 表示・演出。
- 各ケースの期待値は、可能な限り**保存データ(`localStorage`)と画面テキストの両方**で確認する。ただし `g.phase` が `"lost"`/`"ending"` の間は中断セーブへの保存を意図的に止めている設計のため、その2画面への遷移確認は DOM 文言のみで行っている(該当テスト参照)。

### テストの型

| 型 | 何を検証するか | 書き方 |
|---|---|---|
| **状態遷移系** | 画面を操作した結果、`g` と保存データが期待通りか | `click()` → `flush()` → `readGame()`/`readMeta()` |
| **クラッシュ耐性系** | 壊れた/欠損したセーブを読み込んでも例外を投げないか | `localStorage` に直接壊れたJSONを仕込んで `render` する |
| **連打・競合系** | 同一ボタンの多重タップ、異なる2ボタンのほぼ同時押しで二重付与・取りこぼしが起きないか | 間に `await` を挟まず `click()` を複数回呼ぶ |
